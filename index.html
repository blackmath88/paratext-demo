The acts

00

Presentation

Text is never just there.

It is somewhere: separated from the world around it and framed. Measure, typography, alignment, spacing, position and viewport already constitute a presentation.

01

Page

The frame becomes a page.

The page gives text boundary, measure, position and separation from the world around it. Paper and margin resolve around the same continuous body of text.

02

Outside voice

Another voice finds a place in the margin.

Readerly commentary enters from outside. The material frame expands to admit it, and the margin becomes usable semantic space without yet becoming standardized apparatus.

03

Apparatus / print

The margins become part of the system.

What readers improvised becomes repeatable apparatus: notes, references, titles, numbering and hierarchy. Commentary found the margin; print makes the margin systematic.

04

Editorial composition

The frame begins to direct attention.

Composition becomes part of the argument. A construction grid makes measure, hierarchy and the relationship between argument and source explicit before it recedes.

05

Editorial spread

Composition becomes an instrument.

Text, image, diagram, caption and hierarchy can be orchestrated into one reading field. Sophisticated framing coordinates heterogeneous material before the frame becomes computational.

06

Hypertext

Then the frame changes nature.

The page no longer has to contain the text.

Text folds into a virtual space of many dimensions. Addressable places become navigable without physical proximity, and history makes the route reversible.

07

Application

The frame becomes a window onto state.

We can monitor it. Change it. Act through it.

And now the frame itself is written in language.

Persistent state outlives any one view. We can monitor it, change it and act through it. The same case remains visible as detail, table, action, timeline and monitor; then metatext changes how the frame itself is composed.

08

Fragmented frames

Specific frames become extraordinarily powerful.

And the work fragments between them.

Research, sources, drafts, recordings, files and chat are productive precisely because each is specific: a competent local environment for its own material. Fragmentation happens between them — as each frame claims its contents, related operations are pulled apart and their relationships become stranded in the gaps.

09

AI enters the space

We gave the newest intelligence the oldest interface we had.

The intelligence is new; the form is not. Specialized software collapses into a familiar chat window with conversations, projects, search and a little navigation around one chronological stream.

10

The tube

The chat grows. Its usable knowledge shrinks.

A useful exchange becomes a longer and longer chat.

As new context arrives, earlier knowledge disappears.

Each answer may be useful, but every new turn pushes sources, constraints and decisions farther away. The viewport becomes a narrow working-context window onto a much longer stream: the conversation remembers chronologically while the user loses practical access to what it already knows.

11

Delta / Type anywhere

Delta turns the thread into a surface where you can type anywhere.

Chat appends. A canvas attaches.

A conventional chat has one insertion point at the bottom. Delta turns the thread into a canvas: focus beside a paragraph, code result or artifact and write at the exact place where the new contribution belongs.

12

Delta / Virtualized state

In the conventional workflow, code happens locally and conversation gathers later in a pull request.

Delta DB makes shared file state the source of truth. Checkouts become coherent working views.

The development conversation happens in threads—beside the changing work, not later at the pull request.

VS Code ordinarily edits a local worktree; commits are pushed and a pull request becomes the place where review conversation reconstructs the work. Delta changes both sides of that model: Delta DB holds shared file state while checkouts provide coherent views, and threads become the development room where people and agents discuss and change the project together. A pull request can remain a delivery mechanism without having to contain the development conversation.

13

The proposed extension

The thread does not need one canonical interface.

Same objects. Same identities. Thread, document, review.

If checkouts are coherent views into file state, interfaces could become coherent views into thread state. The same durable objects can move from a chronological thread into document and review projections without being copied or losing identity.

14

The interface grows with the thread

A thread may begin as conversation. It does not have to remain one.

As work develops, its apparatus can develop with it: comments, addresses, indexes, links, decisions, files, timelines and project-specific views. The thread can compose the interface it needs without declaring one frame permanently authoritative.
