Concept note · August 2026

When conversation becomes the interface.

AI changes software work because conversation increasingly becomes the place where intent, decisions, critique and implementation meet. But if language becomes more important, the answer is not less interface. It may be a more dynamic one.

The idea in one sentence Language can become the substrate of work while the interface progressively restructures itself around what the work has become.
01 · Trigger

Delta got very close to something I had been circling around.

In Syntax episode 1029, The Workflow of the Future With Zed, Nathan Sobo describes the thinking behind Zed's new Delta product. The important part for me was not another coding agent. It was the shift in what counts as the source of software.

“Conversations are becoming sort of the source of our code. Code comes out of that. It's a downstream artifact.” — Nathan Sobo, Syntax #1029

Delta attempts to preserve the context between commits: the prompts, the edits, the conversation, the changing work tree, and the collaboration that shaped the result. Instead of treating Git snapshots as the whole history, it captures the work as it unfolds.

That is analogous to something I have been exploring in my own OpenMind work: keeping a shadow memory around the output of a chat — not only the final artefact, but the context, alternatives, decisions, unfinished thoughts and paths that led there. Delta is technically far more sophisticated, but the conceptual rhyme is strong: do not throw away the path just because you have the result.

problem→ conversation→ decisions→ artifact
02 · Challenge

Where I disagree: language is not the only interface.

In the same conversation, Sobo argues that natural language is an increasingly superior interface and that we may need less conventional UI. I agree with the first half much more than the second.

Language has extraordinary expressive power. It is excellent for describing intent: “compare these options,” “find the contradiction,” “turn this into a prototype.” But expressive power is only one job of an interface.

Language

Best for intent, ambiguity, explanation, goals, critique and novel requests.

Direct manipulation

Best when pointing, dragging, selecting, arranging or adjusting is faster than describing.

Visual structure

Best when state, hierarchy, comparison, progress and relationships should be perceived at a glance.

A mouse click is sometimes better than a sentence. A spatial overview is often better than a paragraph. A slider is better than “increase it a little more.” A timeline can reveal something that twenty lines of prose conceal.

Language may become the universal input.
It does not have to become the universal interface.
03 · Concept

Structured language: text that acquires a frame.

The more interesting direction is a hybrid. Conversation remains fluid, but the interface starts to recognize that not every sentence is the same kind of thing.

Some text is a decision. Some is a task. Some is evidence. Some is a hypothesis. Some is an unresolved question. Some is background. Some is already an artefact.

I think of this as structured language, or more literally as a text frame: language remains the flexible material, while the system progressively wraps it in structures that make the work easier to navigate and act on.

Chronology first.

At the start, a conversation is simply a conversation. The order of thought matters.

Topics emerge.

As the conversation grows, related material can cluster into themes and sections.

Objects emerge.

Decisions, tasks, questions, sources and artefacts become addressable things.

Views emerge.

The same underlying body of work can now be shown as chat, document, board, map or decision log.

The interface is not designed once. It crystallizes around the work.

This is the key distinction from simply putting a chat box into an application. The UI is reacting to the meaning of the text, and the user's interactions with the UI become another way of speaking back to the system.

05 · What this could become

From chat history to project memory.

The larger idea is not “AI project management.” It is a persistent work object that can preserve intent, decisions and artefacts while presenting them differently depending on what the user is trying to do.

conversation→ semantic objects→ dynamic views→ interaction

A project does not have one true interface. Sometimes I want the chronological conversation. Sometimes I want only decisions. Sometimes I want the product structure. Sometimes I want a board of unresolved work. Sometimes I want the code or artefact itself.

The important thing is that these are not disconnected exports. They are live views over one evolving context.

Conversation becomes the source of structured work.
Code is one downstream artefact. The interface is another.
