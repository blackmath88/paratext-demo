# Slice B — Projections

- **Persistent objects:** the same 16 durable operation groups and their shared
  `operationStates`; latent `#reframe` projection ports and frame furniture;
  the dormant HTML frame switcher.
- **Transformations:** Recovery's addressed field first becomes the `structure`
  layout, then `spec`, then `essay`. Every operation travels through all three
  arrangements via `tweenOperation()`. Operations outside a projection move to
  subordinate positions at reduced opacity but never disappear.
- **New elements:** no new SVG geometry. Restore the existing semantic frame
  switcher mount and wire its four buttons only when this act has settled.
- **Timeline range:** `.76–.84`, settle at the 70% choreography boundary. The
  `projections` entry moves from `plannedActs` into `acts`.
- **Reduced motion endpoint:** the same timeline seeks to the settled `essay`
  projection. The switcher is then available without transition duration, so
  all four meaningful plates remain inspectable.
- **Performance concern:** 16 state tweens per arrangement, with no cloning or
  layout measurement. Interactive switching kills state tweens before starting
  one bounded shared-state timeline.
- **Visual claim:** one stable body of operations can support several coherent
  unities; the frame becomes a projection rather than a container mistaken for
  the source.
